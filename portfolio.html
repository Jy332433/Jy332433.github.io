Ideation / problem selection 2 · mostly human

Workflow. No persistent agent. Whiteboard sessions with Lek-Heng Lim; Claude used as a sounding board (fresh chat, no harness) when stress-testing intuitions about which knot/link invariants might be expressible at small width.

Example. The "width-3 is the threshold" framing came from a hand-drawn sketch tying braid-group generators to ReLU folding. AI was queried after the fact to surface adjacent literature; the geometric intuition is human.

Theorization / conceptual framework 2–3 · partnership-leaning

Workflow. Claude Code (Opus) used to draft definitional scaffolding for the layer-wise topological-power equivalence between ResNet and Transformer; iterated with the user editing each pass, and a Codex (gpt-5.5, xhigh) consult on the "cross-architecture equivalence" formal statement.

Example. The functor that sends an architecture to its layerwise isotopy-class space was prototyped by CC and rewritten by hand to remove a category-level conflation between objects and morphisms — a concrete instance of FM1 (PROVED-vs-VERIFIED) surfacing at the conceptual layer rather than the proof layer.

Failure modes caught: FM1 (definitional conflation), FM3 (off-tangent drift in framework drafts).

Mathematical proof 2 · mostly human

Workflow. CC produced first-pass proof drafts of intermediate lemmas; user edited heavily, with adversarial Codex review (xhigh) for soundness. No Lean formalization on this paper — review was prose-level + sympy spot-checks.

Example. The "ResNet realizes any width-3 isotopy class within O(depth) layers" proof went through three CC drafts; Codex caught a missing case where the residual stream allows zero-width skip identifications, which the user then patched by hand.

Failure modes caught: FM1, FM10 (anti-laziness — user forced direct reasoning over a layer-counting subcase that CC initially tried to script around).

Coding implementation / experiments 4 · mostly AI

Workflow. CC + Opus subagent swarm (parallel Agent tool) for the small validation experiment showing width-3 networks learn target braid invariants in practice. User directed scope and spec; CC handled PyTorch glue, training loops, and plotting.

Example. 3-Opus parallel dispatch: one subagent on data generation (random braid-word sampling), one on the training harness, one on the figure pipeline; results merged into a single notebook by the orchestrator agent.

Failure modes caught: FM4 (caught an early CC attempt to fabricate "convergence" by tightening tolerance instead of training longer).

Paper writeup 4 · mostly AI

Workflow. CC + Codex tag-team. CC for first-pass exposition and figure captions; Codex (xhigh) for adversarial editorial review (tightening claims, flagging overclaims). User edited final.

Example. The abstract went through four cycles: CC draft → Codex critique → CC rewrite → user final. Codex flagged the original phrase "transformers are topologically equivalent" as load-bearing-vague; user replaced with a precise "isotopy-realization equivalence at width ≥ 3" formulation.

Failure-mode catching / verification 1 · human-only

Workflow. No automated verifier. Adversarial Codex review supplied candidate failures; the call on whether each was a real defect or a false alarm was made by the user. Final acceptance was a human judgement.

Example. Codex flagged seven candidate issues across the proof; user confirmed three as real (and patched), three as false alarms, one as out-of-scope. The decision-making layer was deliberately not delegated.

Ideation / problem selection 1 · human-only

Workflow. No AI. Problem chosen from a conversation with Lek-Heng Lim about deformation theory of polynomial-ring quotients; conjectures stated by hand before any agent was given access to the codebase.

Example. The conjecture that the bigraded Poincaré series factors along a specific recurrence in N was written down on paper before any computation. Subsequent CC pipelines were stood up to test it — not to find it.

Theorization / conceptual framework 2 · mostly human

Workflow. Persistent CC subagents via the local relay (cc_relay.py, port 9120): roles rep_theory (sonnet) and formula (opus) running in parallel. Both produced framework drafts on Hochschild cohomology of quotient rings; user shaped the drafts toward the specific T/(det) case.

Example. CC drafted the bar-resolution viewpoint and a Koszul-complex viewpoint as candidate frameworks; user selected and synthesized them (the bar resolution turned out to expose the symmetry the conjecture exploits).

Failure modes caught: FM1 (CC initially treated m=1 verification as proof of the general case — this was the canonical instance that motivated the project's strict label vocabulary).

Mathematical proof 3 · partnership

Workflow. True partnership across CC, Codex (xhigh), and Opus subagents. The proof-status discipline (PROVED+REVIEWED / PROVED / VERIFIED / CROSS-VALIDATED / BELIEVED / OPEN) is the load-bearing constraint — nothing is labelled PROVED until three clean adversarial-review rounds in a row.

Example. The vanishing of HH2 in degree (p, q) for a specific range was developed iteratively: Opus drafted a spectral sequence collapse argument, Codex flagged a missing differential, an Opus subagent patched it, the user signed off after a final Codex round.

Failure modes caught: FM1 (multiple rounds of "PROVED" downgraded to "VERIFIED"), FM2 (cron-driven anti-defeatism kept agents on a stuck differential for three days until it cracked).

Coding implementation / experiments 5 · AI-led

Workflow. CC orchestrated Macaulay2 / Singular / SageMath jobs on the UChicago cluster (fe.ds). 6-Opus + 2-Codex parallel dispatch pattern; user supervisory only (specs, sanity checks at integer-bigraded boundaries).

Example. The N=5, d=4 Poincaré series verification ran across 8 simultaneous Singular jobs feeding a sympy aggregation script; CC wrote the job dispatcher, the result-merger, and the cross-validation harness across three symbolic engines. User reviewed the final table.

Failure modes caught: FM10 (an early CC pipeline tried to summarize Singular output via grep instead of reading; supervisor agent caught it and forced direct reasoning).

Paper writeup N/A

Writeup not yet started. Manuscript pipeline planned; will be re-rated when drafting begins.

Failure-mode catching / verification 1 · human-only

Workflow. User-defined label discipline; user wrote and maintains the PROVED / VERIFIED / CROSS-VALIDATED label vocabulary. Adversarial review is mostly agent-driven (Codex xhigh + Opus pair-review), but the meta-rule — what counts as a clean round, when a label is allowed to upgrade — is enforced by the user.

Example. The canonical FM1 instance: an Opus subagent labelled the m=1 family proof as PROVED for the general statement. User caught it during a routine status review, downgraded the label, added the explicit m=1 qualifier to the vocabulary, and propagated the rule across all subagents' system prompts.

Failure modes caught: FM1 (canonical), FM3, FM9 (motivated the project's progress-flowchart dashboard, progress_flowchart_v2.html).
